Read this first

The issue list is not dozens of unrelated projects. Most failures are different symptoms of seven implicit boundaries: identity, delivery, lifecycle truth, mutation atomicity, recovery, fleet observability, and provider/host execution. Orca already has strong SQLite dispatch records, capability fencing, worker settlement, and transcript archives. The plan below adds durable facts and projections around those foundations; it does not replace the orchestration kernel.

Decision: vNext introduces no fundamentally new orchestration paradigm. It combines proven patterns—durable mail and receipts, provider adapters, server-owned execution, leases, append-only evidence, explicit unknown states, and fleet projections—into one consistent Orca contract.
Evidence status: “Work / Worker / Message / Attention” is a design hypothesis from the ergonomics review, not a concept already established by Orca, GitHub users, or another orchestrator. The evidence supports reducing cognitive load and making the next action obvious; it does not yet prove those exact four labels are optimal. Keep the labels provisional until the validation protocol below is run.

Validation protocol before locking labels or commands

  1. Task benchmark: give agents five workflows—one worker, parallel fan-out/join, ask/resume, queued prompt during a busy turn, and uncertain remote recovery.
  2. Compare variants: current CLI, current CLI plus improved wording, and any proposed aliases such as wait or work start.
  3. Measure: time to first correct command, number of commands, retries/duplicate sends, wrong-target mutations, help lookups, and successful completion without coordinator intervention.
  4. Human comprehension: ask operators what each command will do before execution; record misinterpretations of flags such as --attention.
  5. Decision rule: keep a new noun/alias only if it improves task success and reduces errors without hiding necessary recovery information. Otherwise keep the existing command and improve its output/help.

The user-visible contract

When an agent sends a message

Today, the SQLite message is durable and replayable, but the wakeup is mostly an in-memory waiter or an advisory PTY pointer. A process restart can lose the immediate nudge even though the message remains safe; Orca must redrive only after a fresh live-idle observation or explicit check. A sender normally sees only Sent <message-id> or relay Queued.

During a busy Claude/Codex turn, terminal send --enter may report agent_prompt_stalled even when the text is queued in the TUI and later consumed. Retrying then duplicates the prompt.

mail: recorded → routed → ackednudge: pointer written → submit ambiguous/confirmedprompt: bytes written → submitted → turn startedworker: report persisted → settled

These are separate receipt domains, not one total order. Not every provider can prove every stage; the receipt names the furthest proven fact and an idempotent wait/recovery operation.

When a coordinator reads a worker

worker-read --source auto prefers a bounded decoded projection from the currently selected provider session and falls back to redacted PTY output with a reason. Attach-time binding is not yet guaranteed; cursors are scoped to dispatch, process incarnation, source identity, and position.

terminal.read is provider-neutral PTY output. Claude Code may expose only the visible ~50-line screen while Codex exposes a much longer buffer. Therefore a raw screen cannot be the confirmation or full-scrollback contract.

Rule: provider transcript and submitted-prompt history are evidence; screen text is advisory. Remote/SSH relay loss is unverifiable, never exited.

Implementation DAG

Each node is a bounded agent-sized workstream. A worker owns its tests and contract; it should not silently change another node’s projection or invent a second state store.

P4 schema work may start early, but recovery behavior should consume the P1/P3 authority and outcome contracts. P6 is deliberately last: it projects facts instead of creating another source of truth.

Workstreams: exactly what each implementation agent owns

P0 · Contract vocabulary

Benefit: everyone sees the same honest states.

Do: publish the state/authority matrix; define receipt stages; define live/unverifiable/exited; add duplicate/late/reordered event fixtures.

Do not: migrate behavior, rewrite the scheduler, or add AI policy.

Touch: shared status types, docs, orchestration test fixtures.

Verify: legal-transition, idempotency, replay, and old-client omission tests.

unblocks all

P1 · Stable identity + authority

Benefit: a retry or nested worker cannot complete the wrong lane.

Current gap: capabilities and pane/process checks are strong. The main risk is duplicating identities that already exist.

Do: formally treat immutable dispatch_contexts.id as the Attempt ID and retain the existing terminal Resource ID; add only retry-of, creator/role, and endpoint-incarnation facts; expose parent/depth and unsupervised state.

Do not: add parallel Attempt/Resource tables, infer identity from titles/model text, or remove legacy handles.

Touch: db/dispatch-context/*, db/worker-dispatch/*, lifecycle reconciliation, migrations, RPC caller identity.

Verify: stale retry, pane remint, process mismatch, nested completion, legacy backfill, and identity spoof tests.

depends on P0parallel

P2 · Durable mailbox + wakeups

Benefit: messages are not lost or falsely failed, and agents do not resend duplicates.

Current gap: mail rows/replay are durable, but notification is fallible. The proven duplicate hole is commit-versus-notify; a read/register race is not established on the current synchronous path.

Do: complete the mutation receipt and durable nudge outbox before notification; keep separate mail, pointer, and prompt receipt domains; return queued_pending_turn for accepted TUI input; make pointer injection advisory and redrive only after a fresh live-idle observation.

Do not: collapse all stages into one total order, auto-resend ambiguous prompts, or add an unnegotiated stream opcode.

Touch: db/messages/*, run-delivery.ts, mailbox pointer/notification modules, mutation executor, runtime waiters, orchestration CLI/RPC.

Verify: crash-after-commit/notify for send and reply, pointer-before-Enter crash, queued-mid-turn no-duplicate, restart/live-idle redrive, ack/replay races, and cross-run authorization.

depends on P0parallel

P3 · Attempt lifecycle + completion truth

Benefit: the coordinator can distinguish running, finished, and unknown.

Current gap: worker_done settlement is transactional, but several writers can update worker/context state independently; closed SQLite status checks constrain additive enum changes.

Do: first route every lifecycle writer through guarded transition primitives that update legacy projections and append receipts atomically; then add richer observation/outcome projections and clock-domain-safe freshness.

Do not: widen legacy enums in the first slice, infer success from quiet PTY/Git cleanliness/prose, or collapse SSH loss into exit.

Touch: dispatch context DB, worker stage/start/federated writers, Task writers, lifecycle coordinator, heartbeat and receipt RPCs.

Verify: direct-update ratchet, rollback injection, event ordering/replay, active-sibling races, report-after-reconnect, missing report, clock skew, and SSH verdicts.

P0 + P1 + P2

P4 · Recovery + resource leases

Benefit: restart, stop, retry, and explicit release/recovery converge without killing the wrong process.

Current gap: ownership/release fencing is strong, but stop, abandon, local release, and federated release have different archive/liveness semantics.

Do: preserve the existing resource accounting, ownership/release fencing, archive-before-close/liveness truth, explicit retain/release, and remote release/archive behavior. Specify stop versus abandon versus release separately and add recovery receipts only for observed operations.

Validate first (deferred follow-up): retention-expiry metadata, TTL policy, and paginated/bulk cleanup. Instrument retention reason/age and run the existing dry-run protocol against external, user-owned, transferred, federated, and unverifiable resources; promote only with explicit policy/fencing acceptance tests. Until then, reuse single-resource release/recovery and do not release automatically.

Do not: create a second lease table, close broad panes, auto-release external/user-owned resources, duplicate ownership on retry, or let a recovery heuristic override takeover/identity conflict.

Touch: worker dispatch/terminal DB, ownership/release reconciliation, federation control, archive reader.

Verify: false-exited archive reads, stop output-loss receipt, abandon retention, release identity conflict, reconnect, and remote release. The deferred follow-up uses retention reason/age measurements, dry-run cleanup, and policy/fencing acceptance tests; this is not a committed TTL/cleanup implementation.

P0 + P1 + P3 Retention/TTL/cleanup: validate first

P5 · Provider transcript/read contract

Benefit: coordinator evidence is consistent across Claude, Codex, folders, SSH, and WSL.

Current gap: provider maps and watchers already exist, but direct SSH transcript selection can resolve in the client process and attach-time exactness is overstated.

Do: consolidate existing provider profiles; carry host/connection identity into session resolution; route direct SSH through a negotiated remote read, WSL through guarded UNC on the Windows host, and federation through the peer; expose source exactness/completeness/fallback metadata.

Do not: invent a universal transcript format, read remote files from the desktop, claim attach-time binding without persisted evidence, or replace PTY UX with JSONL. Gate any in-flight mirror on P1/P4 and a demonstrated failure case.

Touch: native-chat/*, worker transcript/output readers, terminal query RPC/CLI, provider profiles, archive/relay.

Verify: SSH local-sentinel isolation, WSL UNC routing, cursor/process replacement, archive fallback provenance, Claude short-screen behavior, subscription gaps, redaction, and size limits.

depends on P0parallel

P6 · Fleet query + attention projection

Benefit: one query answers what is running, what needs attention, and the next safe action.

Current gap: workerList already provides a local projection and renderer status is push-fed; the missing work is bounded composition and negotiated remote batching, not a greenfield fleet store.

Do: first extend/combine the existing read-only worker projection locally; then add a per-host batched remote snapshot with budgets, partial-host errors, stable pagination, and no transcript bodies. Project root completion, input, approval, failure, and interruption separately.

Do not: create a second UI state store, add merge/cost policy to the kernel, blanket-suppress notifications, or assume the renderer is polling every lane.

Touch: worker listing/coordinator projection, RPC/CLI list/show, renderer notifications, federation query.

Verify: local projection parity, bounded 100-worker/two-host calls, stale/unknown display, pagination, partial-host budgets, notification coalescing, and redaction.

after P2–P5

P7 · Cross-host/provider conformance

Benefit: the same contract survives mixed versions and remote loss.

Current gap: protocol and relay capabilities already exist, but skew tests and capability caching must begin before the first wire-changing slice.

Do: make old/new DB, RPC, relay, provider, SSH, WSL, and federated fixtures continuous infrastructure; cache unsupported capabilities by peer fingerprint/runtime epoch; add batched host snapshot negotiation.

Do not: defer compatibility to the end, add unnegotiated stream opcodes, or infer process death from client/relay absence.

Touch: federation RPC, SSH/WSL adapters, protocol/capability cache, remote compatibility tests, provider fixtures.

Verify: CI matrix asserting execution-host reads, safe old-peer downgrade, bounded partial-host behavior, and unverifiable on contact loss.

Terminal read: what to copy from the references

Product Default read source Provider-specific? Fallback / remote behavior Orca takeaway
Overstory Runtime adapters and structured headless stdout/EventStore; tmux visibility fallback. Adapter API is agent-agnostic; parsers are provider-specific. Mostly local; no comparable SSH/federation contract. Keep a narrow provider adapter boundary and prefer structured events.
Paperclip Adapter stdout/stderr/system chunks in a durable NDJSON RunLogStore; optional object-storage mirror. Provider-neutral log chunks behind provider adapters. Live tail plus durable archive survives pod loss. Measure Orca output loss first; consider bounded in-flight mirroring only if a concrete gap remains.
Herdr Execution-host terminal history: visible, recent, and detection; passive subscriptions. Read API is agent-agnostic; lifecycle/session hooks are provider-aware. Server owns panes; remote attach reads on the target host; explicit unknown. Keep screen/recent/detection intent distinct; instrument existing subscriptions before adding a passive watch.
Gas Town tmux by default; Claude JSONL watcher and OTel events are opt-in. Lifecycle protocol is generic; transcript watcher is Claude-specific. Restart-first sessions and append-only feed/audit events; no general SSH transcript reader. Use tmux as bounded evidence, correlate output with run/attempt IDs.
Answer to the key design question: transcript reading should be agent-agnostic at the RPC/CLI contract and transport layer, but provider-specific at session discovery and decoding. The default should be “best exact source available”: provider transcript first, bounded PTY fallback with an explicit warning. Raw screen reads remain a separate terminal product.

Current-main behavior worth preserving

Already strong

  • Stable Run, Task, Dispatch, worker, and terminal-resource records.
  • Capability hashes, pane identity, and process-incarnation fencing.
  • Transactional worker start and idempotent worker_done settlement.
  • Heartbeat suppression, retry circuit breaker, and conservative stop/abandon behavior.
  • Archive-before-close and exact terminal identity re-proofing.
  • Execution-host routing for SSH/federation/WSL and live/unverifiable/exited semantics.
  • Transcript-first worker reads with bounded, redacted PTY fallback.

Do not regress

  • Do not make pane handles or terminal titles durable identity.
  • Do not interpret a PTY write, timeout, quiet screen, or missing client as process death.
  • Do not auto-release external, user-owned, transferred, or identity-conflicted resources.
  • Do not trust completion prose over host evidence.
  • Do not read SSH/WSL transcript files from the desktop process.
  • Do not add a remote stream opcode without capability negotiation.
  • Do not require a Git worktree for folder workspaces.

Phased delivery and review gates

  1. Contracts PR: P0, characterization fixtures, shared states, and fake provider/host harness.
  2. Foundation PRs: P1 identity and P2 mailbox in parallel, additive and dual-read where needed.
  3. Truth PRs: P3 lifecycle and P4 leases/recovery after identity and receipt tests pass.
  4. Evidence PRs: P5 transcript/provider capability and P7 federation/SSH/WSL matrix.
  5. Projection PR: P6 fleet query and attention UX, consuming only durable facts from prior slices.
  6. Promotion: after independently merged slices pass the full matrix, change defaults in a small promotion PR; remove shims only when mixed-version telemetry proves they are unused.

Must pass before merge

  • Busy-turn prompt returns terminal_queued/queued_pending_turn, never a hard failure.
  • Retry by operation/message ID cannot duplicate a prompt.
  • Mail survives restart and is redriven only after a fresh live-idle observation or explicit check; replay is labeled and ack is idempotent.
  • Every residual resource has typed ownership/absence, retention reason, and safe next action.

Must pass in the matrix

  • No false ready or exited from weak observation.
  • Claude/Codex/unsupported transcript behavior is explicit and fixture-tested.
  • Local, folder, SSH, WSL, and old/new federation paths preserve host ownership.
  • Screen, tail, transcript, and archive cursors cannot cross process/source boundaries.

Must pass for operators

  • One fleet query replaces per-lane polling.
  • A five-worker wave emits at most one default root completion alert.
  • Input, approval, failure, and interruption remain distinct.
  • Incoming orchestration mail never overwrites or submits a human draft.

Implementation checklist for every worker

Before coding, answer these six questions in the PR description:

  1. Which durable entity owns this state?
  2. What proves delivery, progress, completion, and cleanup?
  3. What happens after restart, duplicate delivery, timeout, or lost remote contact?
  4. Which actor is authorized, and how is a stale Attempt fenced?
  5. What exact safe next action does failure expose?
  6. Can the behavior be tested without reading a screen buffer?

If a proposed feature cannot answer these questions, it is probably adding another projection or heuristic and should wait until the kernel contracts are in place.

Review pass: make the plan ergonomic for agents

Ergonomics hypothesis: keep Run, Task, Attempt, Dispatch, Endpoint, Resource, lease, receipt, and evidence as durable/internal facts. Test whether the everyday agent surface is clearer when it centers on only Work, Worker, Message, and Attention. Stable IDs still appear in JSON and exact recovery commands, but agents should not manually shuttle ten IDs through the happy path.

One primary status, evidence on demand

Do not expose nine receipt stages as peer statuses in the default list. Use one scan-friendly status and show the furthest evidence stage only when expanded.

Agent-facing status Meaning
Starting Orca owns a start request; no execution turn is proven yet.
Working A provider turn or execution activity is observed.
Waiting for input A durable question or approval blocks progress.
Finished A valid result report was persisted and settled.
Needs review Execution appears finished but evidence is missing or contradictory.
Failed A terminal failure is proven.
Connection lost Process verdict is unverifiable; no death inference.

live, unverifiable, and exited remain the exact machine verdicts. Avoid using ready as a human lifecycle label because today it means input accepted.

Shorter happy-path commands

The low-level API remains available, but common actions should require less ID plumbing: 

orca orchestration worker-start \
  --spec "Review authentication error handling" \
  --worktree current --agent codex --json

orca orchestration status                 # current Run, attention first
orca orchestration status --tree          # dependencies and nested workers
orca orchestration check --wait --attention --timeout-ms 900000 --json

Run-scoped task names and --after api,ui should make small DAGs readable. JSON still returns authoritative IDs and exact next actions.

Recommended user-facing wording

Prompt queued

“Queued for the agent’s next turn. No resend is needed.”

Mail saved

“Message saved. The agent has not been notified yet; Orca will retry the wakeup.”

Replay

“Replayed after reconnect; you may have seen this before.”

Ask timeout

“Question is still pending. Resume waiting; do not ask again.”

Skill rewrite: concise, phase-loaded guidance

The current served guide is functionally careful but too flat: it delays the normal loop, repeats ownership/placement rules, and ends with a low-level fallback example that is more memorable than the preferred path. We are borrowing only the reference project’s skill-writing style—compact kernel, progressive disclosure, one owner per reference, and executable recipes—not adopting its product or process methodology. The rewrite should preserve Orca’s safety contracts while changing how information is loaded.

Always-loaded kernel (target 140–190 lines)

  1. Outcome: what “done” means, who consumes the result, and the safe-failure rule.
  2. Role classifier: coordinator, dispatched worker, full handoff, legacy operator, or ordinary terminal agent.
  3. Authority floor: Dispatch owns lifecycle; execution host owns remote facts; contact loss is not exit.
  4. Canonical loop: create/bind Run → create Tasks → start ready wave → wait → process all mail → reuse/retain/release.
  5. Completion: worker_done exactly once, then idle; coordinator accounts for every settled terminal.
  6. Reference router: load conditional guidance only at the action boundary.

The injected worker preamble should be treated as a separately versioned mini-kernel because it carries the exact capability, handle, Task ID, Dispatch ID, and completion command.

Owned references (progressive disclosure)

  • coordinator-loop.md — DAG waves, names, follow-up reuse.
  • worker-contract.md — heartbeat, ask/resume, worker_done, post-completion.
  • placement-and-remote.md — current/folder/worktree/SSH/WSL rules.
  • messaging-and-gates.md — delivery replay, acks, groups, gates.
  • recovery-and-cleanup.md — stop/retry/unknown/retain/release.
  • low-level-topology.md — only when worker-start cannot express argv/topology.
  • legacy-contract-migration.md — only when an authority label or adopted Run is present.

Each reference owns one concern and must not restate the whole kernel. If the CLI cannot deliver references atomically, ship a compact single-file fallback rather than dead relative links.

Skill rules that prevent predictable agent mistakes

Anti-pattern Teach instead
Generic subagent described as Orca orchestration Use Run + Task + worker-start when coordination state matters.
Low-level terminal create + dispatch as the default Use worker-start; load low-level topology only for an expressiveness gap.
Retry after timeout, idle TUI, or remote disappearance Treat as checkpoint/unknown; preserve authority and inspect/reconnect.
Re-ask after timeout Resume the original question message ID.
Release on heartbeat, timeout, or stale report Release only after accepted settlement, and archive first.
